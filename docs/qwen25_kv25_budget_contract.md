## Budget and serving contract

`N` is the actual post-PatchMerger non-structural image-content token count in the LLM prefix. `S` is the count of system/user/vision boundary and other non-image prefix tokens from real prefix IDs and store metadata; Qwen has no LLaVA newline separator rows. For `N>0`, `r=0.25`, `C=64`, select `k=ceil(rN)=(N+3)//4` importance-ranked real stored rows `[0,k)`, and read `m=ceil(k/C)=(k+63)//64` normal chunks `[0,m)`. The same selected positions cover K and V, all native KV heads, and all decoder layers. The generic helper defines N=0 and r=0/r=1 and rejects bad arguments; serving rejects N=0 and an empty selected content set. In general `k/N` may exceed 25% by less than `1/N`.

The store stays full and in its validated image-only global VisionZip permutation. Whole 64-row chunks are read as contiguous spans per layer/kind, including the existing padded last chunk if reached. Real OS-returned bytes and preads, padding, structural sidecar reads, and H2D tensor bytes are separate quantities. Before H2D, trim valid read rows to stored indices `<k`; then restore original logical order and combine all structural prefix rows in the existing P2 compact cache. No extra real or padding rows may appear in the compact cache. Original full-prompt MRoPE, post-MRoPE K, cache positions, causal mask, dtype, decoder and state clearing remain unchanged. Neither online scoring nor query/history-dependent selection is allowed.

Existing v2 stores may be reused read-only only when exact protected `meta.json` SHA256 is registered for each resolved path and its source code revision is the frozen old revision above. Activation must additionally pass the existing complete payload hashes and identity checks for image bytes, checkpoint/processor/environment, prefix IDs, geometry, position policy, native BF16 shape, global permutation and saliency provenance. New stores use the new revision. Full-file integrity I/O is activation cost, never hit cost. Reused stores imply `CACHE-HIT REEVALUATION`; persistence and cold-start session cost are `NOT_REMEASURED`.

## Required correctness gate before pilot

CPU fixtures cover N=1,63,64,65,127,128,129,255,256,257,349,370,1024, N=0, r=0/r=1, invalid inputs, EOF/padding, Qwen structural prefix, real pread traces, extra finite sentinel, 100% inverse identity, unchanged legacy default, and LLaVA helper geometry parity. The required combined Qwen/LLaVA CPU regression is 42 tests. LLaVA GPU is `NOT RUN` unless actually executed.

GPU uses the ten fixed v2 pairs and a prospectively hashed `gpu_freeze.json`. It first reruns the immutable v2 G1-G13 matched-memory/SSD, structural, position, mask, and numerical-branch controls on fresh run-local captures. New gates are:

1. **G1** native BF16 storage round-trip and 100% inverse-repack exact, all layer K/V bits.
2. **G2** FullLoad SSD against matched in-memory FullLoad v2 exact.
3. **G3** KV25 SSD against an independent canonical captured-KV reference: independently stable-rank captured scores, directly gather top-k original K/V and all structural rows, sort by original logical position, then run the same compact shape/backend. Production selection, loader and assembler cannot construct the reference. Require exact BF16 bits, identity, first logits, first token, full generated IDs and prediction; identical repeat inputs must be deterministic.
4. **G4** all 28 layers and 4 native KV heads contain exactly k content rows plus S structural rows; no repeated Q heads are stored.
5. **G5** no extra real or padding rows in compact cache. A large finite BF16 sentinel in the unused read rows must leave assembled KV bits and output unchanged.
6. **G6** independent stock full-logical MRoPE positions, causal visibility and dense/compact FP32 GQA attention oracle; elementwise `atol=1e-5, rtol=1e-5`. Deliberately wrong mapping/position/mask fixtures must be rejected.
7. **G7** first prefill through final decode cache length/position and mutable-state isolation exact, including interleaved image/method requests.
8. **G8** source T1 vision call=1, hit vision=0, online score=0; same image question/history must not change selected IDs.
9. **G9** minimum `ceil(k/64)` chunks, exact planned spans versus independent OS pread returned bytes/calls, no unselected normal chunk; count extra valid and padding rows.
10. **G10** old Chunk25 default reproduces immutable final v2 first-logit hash, generated IDs and prediction, with original v2 gates maintained.
11. **G11** old/new matched-output identity is required only when their selected content sets are equal. The ten fixed real samples have changed sets and extra read rows; no equal-answer claim is made for them. An N=256 synthetic CPU fixture covers an equal-set boundary.
12. **G12** LLaVA Chunk25/KV25 CPU regression and protected-file hash receipt PASS, with LLaVA GPU marked `NOT RUN` if unexecuted.

Exact K/V bits, selection and masks are equality gates. Matched GPU logits and generated sequences remain **bitwise exact**, as in v2; no threshold is relaxed. The old v1 `atol=0.125, rtol=0.02` applies only to separately reported ReComp full-vs-split and dense-vs-compact BF16/NF4 shape diagnostics, not to the matched KV25 gate. A required `FAIL`, `UNRESOLVED`, or `NOT RUN` blocks smoke and pilots. Pilot quality or speed improvement is not a correctness condition.

## Conditional pilot and storage plan

Only after all required gates pass: fixed four-image × three independent-question × four-arm smoke (48 requests), then frozen GQA 40 images × six independent questions × four arms (960 requests), and MT 40 dialogues × three generated-history turns × four arms (480 requests). Arm IDs distinguish ReComp, FullLoad, `qwen_ours_chunk25_legacy` (`budget_unit=chunk`) and `qwen_ours_kv25` (`budget_unit=visual_kv`). T1 is unpruned full-image inference for every arm. MT T2/T3 history contains only that arm's generated previous answers. Execution order rotates deterministically. Every logical request gets a unique physical execution ID; failures/retries remain in raw output.

At freeze, this workspace has about 134.5 GiB free. The validated old GQA and MT stores total about 3.7 GiB and are reused read-only; no duplicate pilot store is budgeted. New ten-pair GPU validation stores and output are conservatively budgeted below 10 GiB, smoke/GQA/MT raw and reports below 2 GiB, with at least 30 GiB free safety reserve. Abort before a write that would violate the reserve, without deleting older files. Exact capacity and compatibility checks belong in `storage_plan.json`.

For hits, true request TTFT starts before prompt/token preparation and includes SSD preads, H2D, compact assembly, prefill, first-token materialization and CUDA sync; request E2E ends after generation. Image file read/decode, model loading, common warmup, `posix_fadvise(DONTNEED)` conditioning and metadata activation are outside TTFT and separately recorded. DONTNEED does not guarantee cold NAND. Old/new use the same captured KV and physical store. Report all/hit/turn quality, logical `k/N` (image mean and pooled), structural-inclusive retention, valid and actual returned read bytes, actual H2D and compact-cache bytes, old/new selected-set/chunk changes, unused boundary rows, TTFT/E2E, and paired image-cluster 10,000-resample CIs with seed 1234. A CI containing zero is not equivalence. MT history divergence is part of method-level outcome, not isolated KV causal effect. Do not import old-run latency or persistence into new measured columns.
