## 설정

- 실행: `runs/mt_gqa_async_20261116T081635Z` (요청 단위 원본), 이 디렉터리(`results/mt_gqa_async_20261116T081635Z`)는 집계와 보고서.
- 환경: Python 3.10.20, torch 2.5.1+cu121, **transformers 4.57.6** (`/home/dblab/anaconda3/envs/mllm_ft/bin/python`). 기존 HOLD 실행과 같은 버전이다. 이전 IMPRESS 단일 턴 작업은 transformers 5.13.1 환경이었다.
- 모델 `llava-hf/llava-v1.6-vicuna-7b-hf` revision `c916e6cdcd76…`, NF4/BF16/eager, FP16 SSD KV, greedy max 16, batch 1, CPU threads 2.
- 모집단·절차: MT-GQA-reconstructed 398 images / 4,061 dialogues / 3턴, method-local generated history, strict normalized EM, 대화 단위 arm 순서 회전. 턴 1은 모든 방법이 픽셀부터 계산, 캐시 예열 없음, 저장 KV 읽기는 요청 직전에 page cache를 비운 cold 조건.
- IMPRESS: probe head 3개, α = 0.6, layer마다 25% 유지, chunk 64 토큰, 중요도 = suffix 행 전체의 attention 열 합(head 평균), fallback은 K 전량 + 선택된 V chunk, 재배치는 첫 대화 턴 1 질문 1개의 중요도 내림차순(layer별), 비동기는 다음 layer probe key 선행 읽기.
- FullLoad: 전체 Visual KV(raster 순서). 비동기는 워커가 layer 순서로 K·V 전체를 이어 읽음.
- Ours: PYR-beta-raw packed store(`layer_budget_kv25_pyrbeta_20261110T073604Z`의 벡터 그대로). 비동기는 워커가 packed 파일을 separator 구간 → layer 순서로 이어 읽음.
- 비동기 공통: 백그라운드 워커 1개, 디스크 읽기만 워커가 하고 GPU 적재는 요청 스레드, 선행 읽기는 TTFT 타이머 시작 뒤에만, 앞서 읽는 깊이 상한 없음.

## 해석과 예상 밖 결과

수치는 위 표에서 가져왔다. 새로 계산한 값은 없다.

- 본실행 GPU가 읽기를 기다린 시간(followup 평균): FullLoad 114.6 ms, IMPRESS 377.0 ms, Ours 7.2 ms. ReComp는 읽기가 없다. 비동기 효과는 DEV와 같은 방향이다.
- **IMPRESS가 FullLoad보다 느리다(TTFT 1.478×, 차이 +233.3 ms [+230.1, +236.5]).** 읽기량이 FullLoad의 약 87%(1020.3 vs 1173.9 MB)밖에 줄지 않고, probe 판정·layer별 중요도 선택 같은 계산 hook과 chunk 단위 pread(요청당 140.1회, FullLoad 64.0회)가 더해진다. 이 보고서는 어느 요인이 얼마나 기여했는지 분해하지 않았다(미실행). 정답률은 FullLoad 대비 차이 미입증이다(−0.18 pp [−0.60, +0.24]; 동등성의 증거는 아님).
- **재배치는 chunk 접근을 줄였지만 읽기량 절감은 작다.** K·V chunk 실측 81.7%, 재배치 없는 순서의 계산값 99.8%. fallback 비율은 29.1%, 평균 Jaccard는 0.364로, consensus가 성립하는 layer는 일부다. fallback layer는 V chunk를 99.5% 읽는다.
- **fallback이 layer에 몰려 있다.** layer 3–5, 8–9, 11–12, 14에서 fallback이 약 70% 이상이다(layer 9는 69.9%). 반면 layer 0–2, 6–7, 10, 16, 22, 25에서는 거의 0%다. 이 패턴의 원인은 분석하지 않았다(미실행).
- **Ours의 정답률이 낮다.** 67.42%로 FullLoad보다 −0.96 pp [−1.60, −0.34], ReComp보다 −1.06 pp [−1.69, −0.44]이고 CI가 0을 포함하지 않는다. 25% layer 예산 방식의 정답률 손실이 이 본실행에서 측정된 것이다. 이 손실은 이번 작업에서 만든 것이 아니다. 기존 HOLD의 Ours와 토큰이 같은 것은 gate와 DEV 요청에서 확인했다. 398장 전체를 기존 HOLD 기록과 토큰 단위로 다시 대조하지는 않았다(미실행).
- FullLoad 비동기는 ReComp보다 TTFT가 낮다(0.921×). 반면 FullLoad의 followup E2E가 ReComp보다 낮은 것은 TTFT 외에 디코딩 시간 차이가 섞여 있어, E2E 차이를 읽기 방식만의 효과로 해석하지 않는다.
- 턴 1 정답률은 네 방법이 모두 63.19%로 같다(턴 1은 모두 픽셀부터 계산).
- IMPRESS의 중요도 집계(508 ms)는 턴 1 추론 밖에서 별도 forward로 잰 값이다. 턴 1 추론에 합치는 구현은 미실행이다.
